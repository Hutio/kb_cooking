# 내 레시피 (개요)

> 직접 만들어 보고 결과를 확인한 레시피만 여기 둔다. 다른 레시피 폴더는 자료를 정리한 것이고, 여기는 **실제로 냄비와 오븐에서 나온 것**과 **다음에 무엇을 바꿀지**를 적는다.

## 시작하기

**다른 레시피 폴더와 무엇이 다른가**

| | 일반 레시피 | 내 레시피 |
|---|---|---|
| 출처 | 자료 조사·검증 | **직접 만들어 본 결과** |
| 수치 | 일반적 기준 | **내 도구·내 재료에서 나온 값** |
| 실패 정보 | 알려진 것 | **실제로 겪은 것** |
| 버전 | 하나 | **시도마다 바뀐다 — 시도 기록에 남긴다** |

### 표시 — 태그와 속성

모든 내 레시피에는 태그 `내레시피` 를 단다(Obsidian 태그는 띄어쓰기를 허용하지 않아 붙여 쓴다). frontmatter 에 아래 속성을 더한다. [[내 레시피.base]] 가 이 속성으로 별점순·상태별 목록을 만든다.

| 속성 | 값 | 뜻 |
|---|---|---|
| `rating` | 0~5, 0.5 단위 | **가장 최근 시도**의 종합 별점. 아직 평가 전이면 비워 둔다 |
| `status` | 완성 · 개선 중 · 보류 | 다음에 그대로 만들지, 고칠지, 접을지 |
| `tried` | YYYY-MM-DD | 마지막으로 만들었거나 기록한 날 |
| `attempts` | 정수 | 지금까지 만든 횟수 |
| `source` | 문자열 | 검증 상태. 문서의 배합이 아직 안 만들어 본 다음 버전이면 "미검증"을 밝힌다 |

### 별점 기준

별점이 시간이 지나도 같은 뜻이 되도록 기준을 고정한다. 사이 점수는 0.5로 준다.

| 별점 | 뜻 | 다음 행동 |
|---|---|---|
| 5 | 그대로 다시 만든다. 바꿀 것이 없다 | `status: 완성` |
| 4 | 만족. 작은 조정만 남았다 | 한 군데만 손본다 |
| 3 | 먹을 만하지만 내가 원한 것과 다르다 | 가장 큰 원인 하나를 골라 고친다 |
| 2 | 핵심 목표를 놓쳤다 (식감·익힘 등) | 배합이나 공정을 다시 설계한다 |
| 1 | 다시 만들지 않는다 | `status: 보류` |

**별점과 함께 무엇이 점수를 깎았는지 세 갈래로 적는다** — 맛 · 식감 · 과정(타이밍·난이도). 같은 3점이라도 맛이 문제인지, 식감이 문제인지, 만드는 과정이 문제인지에 따라 다음에 바꿀 것이 완전히 다르다. 예를 들어 압력솥 동파육 3.2는 식감은 성공, 맛 3.5, 과정(소스 타이밍)이 문제였다.

### 시도 기록 쓰는 법

각 문서 끝의 `## 시도 기록` 표에 한 줄씩 남긴다: 차수 · 날짜 · 핵심 조건 · 결과 · 별점. 그리고 **다음 시도에서 바꾸는 변수는 되도록 하나로** 줄인다. 여러 개를 한꺼번에 바꾸면 결과가 좋아져도 무엇 덕분인지 알 수 없다.

**같은 요리가 일반 폴더에도 있으면** 원리와 배경은 일반 문서에, 내가 검증한 배합과 판단 기준은 여기에 두고 서로 링크한다.
